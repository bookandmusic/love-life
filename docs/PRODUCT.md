## 一、产品定义

### 1.1 产品概述

#### 1.1.1 产品定位

一款面向**单一情侣**的**生活记录与情感管理应用**，帮助情侣双方共同记录日常、管理回忆、追踪足迹、维护纪念日，并通过 AI 智能助手降低使用门槛。

> **产品形态**：自部署、自用——以自部署软件形态发布（服务端二进制 / Android APK / Docker 镜像），服务运行在部署者自己的服务器（NAS / VPS）。
>
> 部署与运维方式（TLS / 反代、进程管理、备份）**由部署者自选**；非多租户 SaaS，无应用商店上架与合规负担，无第三方接入审批流程。
>
> **全部数据自包含于一处，核心数据不流向第三方。**

#### 1.1.2 产品组成

| 组件 | 面向谁 | 做什么 |
|:---|:---|:---|
| **手机 APP** | 情侣双方 | 日常记录与浏览主力终端，双模式界面（传统 + AI 对话） |
| **Web 后台管理页面** | 部署者（admin） | 系统配置、模型管理、审计监控 |
| **后端服务** | — | 数据的权威存储与业务处理；部署形态见 ARCHITECTURE「部署形态与产物」 |

#### 1.1.3 核心理念

- **传统模式**：完整的、可手动操作的情侣生活记录 APP
- **AI 模式**：独立的全屏对话窗口，所有功能通过自然语言对话完成
- **两套逻辑并行**，互不干扰，共享同一套底层数据与业务服务
- **数据操作原则**：只增不删（软删除），记录内容不可编辑，回收站兜底；配置信息（用户资料 / 空间配置）可修改
- **出站第三方依赖只有三类**：模型 API、地图瓦片、通知 Webhook；其余一切（含逆地理）在本地完成，核心数据留在自部署服务器

### 1.2 角色与账号

| 维度 | 说明 |
|:---|:---|
| 账号体系 | 系统不提供注册；管理员账号在首次部署时确定，之后由部署者自行保管 |
| 冷启动 | 部署 → admin 登录 → 添加情侣信息（girl / boy） |
| 角色 | admin（部署者） / girl（女方） / boy（男方） |
| 权限分层 | admin 拥有系统配置权（模型 / MCP / 回收站 / 审计）；情侣用户专注内容操作 |
| 密码重置 | girl / boy 忘记密码由 admin 在后台管理页面重置（无自助找回，不依赖外部邮件 / 短信服务） |
| 登录入口 | APP / Web 后台共用同一登录系统；APP 仅接受情侣角色（girl / boy），admin 只能登录 Web 后台 |
| 未登录状态 | 所有页面重定向至登录页，无公开匿名访问 |
| 登录态时长 | 登录一次后**长期保持**（不必频繁重输密码）；长时间未使用的登录凭据会被系统作废，此时重新登录即可。作废机制与时限见 ARCHITECTURE「统一登录与认证」 |

> **核心原则**：用户侧客户端只有手机 APP；Web 后台管理页面面向 admin。认证机制见 ARCHITECTURE「统一登录与认证」。

### 1.3 双模式界面

#### 1.3.1 双模式对比

| 维度 | 传统模式 | AI 模式 |
|:---|:---|:---|
| 交互方式 | 点击、滑动、表单填写 | 自然语言对话 |
| 操作粒度 | 用户手动完成每一步 | AI 理解意图，批量执行 |
| 适用场景 | 精细操作、浏览回顾 | 快速记录、批量整理、模糊查询 |
| 学习成本 | 需理解页面结构 | 只需会说话 |
| 确认机制 | 操作即生效 | AI 生成预览，用户确认后生效 |
| 数据权限 | 用户直接操作 | AI 以用户身份代理操作，写操作需发起人确认 |

#### 1.3.2 模式切换与状态

- 切换入口：**设置页**切换传统模式 / AI 模式
- 两种模式互相独立：
  - 传统模式：展示为主，按钮简洁，删除等操作不干扰视觉体验
  - AI 模式：支持文字输入（发动态时可选媒体；**不支持语音输入**），确认卡片 / 图片展示 / 统计概览等丰富交互
  - AI 可用性：服务端未配置模型 Key 时，AI 模式切换项置灰并提示（无 Key 即不可用，后台不设独立开关）
- AI 模式内直接展示结果，**不做跨模式跳转**
- 状态保持：
  - 传统模式：记住上次浏览位置
  - AI 模式：对话历史跨设备一致、不自动过期（删会话即清空）；本地缓存只是加速，不作为权威

## 二、界面与功能

### 2.1 传统模式 — 页面与功能

**底部导航（五个 tab）**：首页 / 动态 / 相册 / 纪念日 / 地图。

**右下角浮动添加按钮（FAB，添加菜单）**提供四个入口：记动态 / 添加地点 / 纪念日 / 相册——**无独立「传媒体 / 传照片」入口**。

- **通知 / 设置入口**：显示范围见「通知中心」

#### 2.1.1 首页（纯情感仪表盘）

- **顶部：关系状态栏（情感展示）**
  - 双方头像 & 昵称
  - 在一起天数（未设置在一起日期时不显示天数，改显示一句引导文案；日期由后台空间管理维护，见「后台管理页面功能范围（admin）」）。开始日**不能晚于今天**：后台保存未来日期一律拒绝并提示，从写入侧杜绝「1 天 / 0 天」这类无意义天数
  - 下一个纪念日倒计时
  - 右上角：通知铃铛（红点，进入通知中心）+ 设置图标（进入设置页）
- **中部：卡片区**
  - 回忆精选：从历史照片 / 动态池随机抽取，常驻兜底卡（每次进入可刷新）——只要存在历史照片或动态，首页必不空（全新部署除外，见下一条）
  - 那年今日：同月同日历史回忆入口卡（显示篇数，有数据才出现）
  - 全新部署无任何数据时：与其余页统一的空态（图标 + 短标题 + 一句短提示，见「图标与插画」），引导创建第一条内容。空态判定用**计数**（动态 / 纪念日 / 相册三者皆空）而非「有无下一个纪念日」——否则「纪念日存在但日期全部无效」会被误判成空态
- **底部：无添加入口**（所有添加统一走右下角 FAB，含快捷创建纪念日 / 动态，复用现有能力）
- **发布动态**：右下角浮动添加按钮（FAB）→ 记动态（媒体随动态）

> 提醒类内容（新动态提醒 / 足迹更新 / 相册上新）统一收敛至通知中心（见「通知中心」）。

#### 2.1.2 动态

> 「动态」为底部导航 tab 之一（动态列表）；相册为独立底部 tab（见「相册（独立底部 tab）」），不挂在「动态」内。

- **中部：动态列表**
  - 按时间倒序展示所有动态
  - 滚动加载：滚动接近底部时自动拉取下一页（页头不设刷新按钮）
  - 动态卡片（文字 / 媒体 / 地点 / 心情 / 点赞 / 收藏 / 评论数）
  - 卡片内完成全部操作
    - 点媒体进全屏查看器：照片可缩放、视频 / 音频点击播放、多张可左右切换、「保存」到本机
    - 点赞 / 收藏
    - 展开评论列表与发表评论
  - **全屏查看器的界面约定**（三类媒体共用同一个查看器，时间轴 / 动态 / 相册三处一致）
    - **顶部**：类型标识（照片 / 视频 / 录音）与序号
    - **底栏**：「保存」+ 类型提示，**提示按类型换文案**——照片为「单击媒体可放大 / 左右滑动切换」，视频与录音为「点击播放 / 左右滑动切换」
    - **窄屏下按钮与提示各占一行**，不并排挤压
  - **无动态详情页**：卡片已展示全文与全部媒体；通知 / 首页回忆卡 / 相册「查看所属动态」等入口跳时间轴并定位高亮该条

#### 2.1.3 发布动态

> 媒体只随动态存在（删除动态即删除其媒体，见「相册（独立底部 tab）」）。

- **正文**：文字（可选，可留空只传媒体）
- **媒体**：图片 / 视频 / 音频多选（可选），**单条最多 9 个**；以方格网格预览，最后一个格子为「+」，支持连续追加；点选 X 移除单张
- **附加信息**：
  - 地点（可选）：输入地名得到候选列表；无满意结果时可在内置迷你地图上直接点选坐标（见「地图」）
  - 心情标签（可选）：温馨系预设 + 自定义输入
- **媒体处理**：图片生成缩略图、视频用占位图；拍摄时间取照片自带信息，**不读取照片的位置信息**
- **提交时才上传**：选择阶段文件只在本机预览——**没点 [发布]，文件从未离开设备**；点 [发布] 时整批逐个上传（可见逐文件进度），全部就绪即自动发出动态，中途重传无需再点。**个别媒体上传失败不半发**：动态不发出，失败的媒体单独重传（其余不重来），全部就绪后自动完成提交。AI 模式的「确认执行」同此规则（见「图片与「看图」边界」）
- **放弃发布的收尾**：关掉页面、取消发布——这些文件**不会变成你的内容、也不会在服务端驻留**，已上传的部分被立即撤销清理，用户无需手动处理，也看不到残留。机制见 ARCHITECTURE「媒体上传管线」
- **发布条件**：正文 / 媒体 / 地点 / 心情 至少一项（不允许空动态）
- 操作：[发布]

#### 2.1.4 地图

- **顶部：视图切换**：地图视图（默认） / 列表视图（管理所有点位）
- **中部：足迹展示**
  - 地图视图：显示所有地点点位
  - 列表视图：查看点位 / 删除点位（软删除进回收站）
- **地理编码**：输入地名返回候选列表（名称 / 归属地 / 经纬度）；候选都不满意时支持「地图选点」兜底——在迷你地图上点选直接取得坐标
- **添加地点（表单页）**：FAB「添加地点」→ 完整表单页（名称 + 搜索候选回填 / 地图选点 / 手动经纬度 + 保存）
- **点位来源**：双来源进同一点位池——① 动态带地点时自动同步生成（地点名相同则复用已有点位，坐标以先创建者为准）；② 手动创建（地图页表单、AI 口语报点）
- **未配置瓦片源**：无「使用中」瓦片源时，地图视图与添加地点 / 发布里的迷你选点图显示全站统一空态（「图标与插画」：「地图还差一块底图」+ 引导至 后台 → 外部集成 → 地图配置 启用瓦片源）；列表视图不受影响，选点仍可走地名搜索 / 手动经纬度

#### 2.1.5 相册（独立底部 tab）

> 相册为独立底部 tab；创建通过全局 FAB「相册」→ 自动弹出创建 Sheet。

- **顶部：视图切换**：时间轴视图（默认） / 集合视图（手动相册）
- **中部：内容展示**
  - 时间轴视图：**未归档**的照片 / 视频 / 录音按时间排列（三类进同一个全屏查看器；已归属相册的媒体不在时间轴，移出相册即回到时间轴）
  - 集合视图：展示所有相册封面
- **底部**：无添加入口（创建走全局 FAB「相册」）

> **媒体来源模型**：所有媒体随动态发布进入时间轴，**删除媒体 = 删除整条动态**（时间轴 / 集合内均无独立媒体删除按钮，也不能新创建独立媒体）。相册内支持「移出当前相册」（媒体回到未归属状态，不删除，仍在时间轴）与「查看所属动态」（跳时间轴并定位高亮该条，见「动态」）。
>
> **相册归属规则**：一个文件只能归属一个手动相册（全相册唯一）；已归属的文件不能再加入其他手动相册（选图器置灰并显示所属相册名）。
>
> **收藏进集合**：时间轴视图支持多选 → 「加入相册」（选择已有相册或新建并加入）；已归属媒体重复加入时提示冲突。
>
> **相册详情添加入口**：手动相册内照片网格末尾为「+」格子（最后一个图片图标）；点击打开与时间轴 tab 视觉一致的按月分组选择页，已归属本相册 / 其他手动相册的媒体灰显禁止选择（tag 显示「已在本相册」或所属相册名），未归属媒体多选后「加入相册」。
>
> **月度相册**：集合视图里按自然月自动分组的**展示形态**，不是真实相册——没有独立的册子实体、不需要手动创建、也**没有隐藏开关**（无可隐藏的对象）。**有几个月亮几个月**：凡该月存在未归属媒体的就出现一组，无照片的月份不出现；点进去看该月未归档媒体，与手动相册同列于集合视图（列表行标注「月度」 / 「手动」）。聚合口径见 ARCHITECTURE「内容」。

#### 2.1.6 纪念日

- **中部：纪念日列表**
  - 展示所有纪念日（名称 / 日期 / 倒计时），全部按年重复循环（无一次性纪念日）；农历条目行主标题 + 两行副行（`年 · 农历X月X日` 与 `下个公历 YYYY-MM-DD`）
  - 每个卡片支持删除（移入回收站，不可编辑）
- **添加与管理入口**
  - 添加入口：右下角 FAB → 纪念日；页头不设添加按钮，空态带「记下第一个纪念日」引导 CTA（与全站空态口径一致，「图标与插画」）
  - 添加为完整表单页：标题 + （阳历 / 农历）切换 + 日期
    - 阳历：直接选择公历日期
    - 农历：在月份滚轮里选择农历月 / 日（存在闰月时，闰月在滚轮里作为「闰X月」选项紧跟同名平月之后，符合农历书写习惯），实时显示对应公历日期
    - 月 / 日选择器一律用**农历汉字写法**（正月…腊月；初一…初十、二十、廿一…廿九、三十），不用阿拉伯数字
  - 日期语义与换算口径见 ARCHITECTURE「内容」 Anniversary
  - [提醒设置]：每个纪念日配置提前提醒天数（0-90 天，默认 1 天；0 表示当天提醒）；提醒同时进通知中心与已配置的外部渠道（站内+外部同发）

#### 2.1.7 设置

> 入口：一级 tab 页右上角设置图标（AI 对话页右上角仅设置、登录页除外）；本页为纯设置页，不含任何内容浏览或快捷跳转。
>
> 资料与空间类配置（我的资料 / 情侣空间信息）不在 APP 设置页，统一由后台管理页面维护（见「后台管理页面功能范围（admin）」空间管理），APP 只做业务数据管理。**AI 偏好（输出风格）属个人体验项，保留在 APP 设置页**。

**本页按模式分层**：通用项**始终显示**，模式专属项**只在该模式下显示**——切到哪个模式，就只看到那个模式的设置，不把两套模式的配置堆在同一屏。**只列不藏**：任何一项都不因为当前模式而消失于文档，只是显示时机不同。

- **通用**（两种模式都显示）
  - **模式切换器**：传统模式 / AI 模式二选一，切换后立即生效；AI 不可用时 AI 项置灰并提示原因
  - **外观**：深浅模式（跟随系统 / 浅色 / 深色）；强调色（暖色系预设色板）
  - **其他**：关于（版本号 / 服务端地址 / 项目主页）；退出登录
- **仅 AI 模式显示：AI 偏好**（个人体验项，仅该用户发起 AI 会话生效）
  - 输出风格：文艺 / 幽默 / 简洁
- **仅传统模式显示**：当前无专属项——传统模式的功能入口在各业务页面内（发布走 FAB、删除走长按等），设置页不为它塞入无意义的开关
- **本机存储与缓存（两模式通用，但不出现在设置页）**
  - **媒体另存到本机**：单条媒体底部「保存」走系统「另存为」；无批量保存、保存完不发通知。**这不是数据导出 / 备份**（备份由部署者拷贝数据目录完成）
  - **本地缓存**：自动管理（容量上限 + 按使用情况自动淘汰旧内容），设置页**不提供手动清理入口**
- **设置页不含**：模型配置项（API Key、模型选择、自定义端点等，全部由后台服务管理）、回收站入口（仅后台管理页面可见可操作）、AI 操作记录（审计统一归后台「审计日志」）

#### 2.1.8 通知中心

- **入口**：通知 + 设置按钮的显示范围分三档
  - 一级 tab 页顶部右上角：通知铃铛 + 设置图标
  - AI 对话页：仅设置图标（不含通知铃铛）
  - 通知 / 设置 / 发布 / 详情等二级页面：不显示
- **内容**：通知列表按时间倒序，覆盖以下事件
  - **新动态** / **点赞** / **评论** / **收藏** / **纪念日提醒**
  - **足迹更新**：手动建点或 AI 口语报点时报另一方；**动态带地点自动生成的点位不另发**
  - **相册上新**：对方创建手动相册时（含 AI 代建）；**自建静默**
  - **内容删除**：**仅当对方删除你发布的内容时产生；删除自己的内容静默**
  - **事件类型清单与推送口径见 ARCHITECTURE「通知分发器」「通知与回收站」**
  - **点赞 / 收藏：允许自赞 / 自藏；任何一方动作（含自己赞 / 藏自己发布的动态）都通知另一方，评论同口径**（传达「我在意这条内容」）
- **交互**
  - 点击通知**跳转对应内容**：动态时间轴并定位高亮该条 / 地图点位 / 纪念日卡片 / 相册详情
  - **内容删除通知无跳转**（内容已不可见）
  - 红点随已读消除；支持「全部已读」一键批量标记
- **边界**：站内通知中心始终全量收录、不设站内开关；外部推送按渠道的事件订阅配置（渠道为空间级、仅 admin 后台管理）

### 2.2 AI 模式 — 界面与能力

#### 2.2.1 界面结构

> 本节只讲**骨架**（有哪几块、各放什么），具体呈现见「消息呈现」「过程呈现」，卡片见「卡片体系」。

- **顶部栏**（三块）：
  - **[菜单]** 左上角：会话抽屉——会话列表 / 新建 / 切换 / 删除
  - **「我们的 AI 助手」** 标题
  - **[设置]** 跳转设置页，可在设置页切换回传统模式
- **对话区域（主体）**：滚动区，自上而下依次是消息（「消息呈现」）、过程条目（「过程呈现」）、结果卡与确认卡（「卡片体系」）
- **底部输入区**：「+」 / 文本输入框（支持多行） / [发送]；AI 不可用时三者全部禁用并展示原因，文案与设置页 AI 模式置灰提示同一口径（「设置」），避免发出注定失败的请求
- **视觉风格**
  - 背景暖灰 `#F0EDE8`
  - 气泡无尖锐棱角、padding 宽松
  - 字体与传统模式一致
  - AI 头像用专属标识（区别于伴侣头像）
  - 整体氛围安静、专注、可信赖

#### 2.2.2 消息呈现

- **气泡**：AI 消息左对齐、浅暖灰底；用户消息右对齐、主色调底
- **Markdown**：AI 回复按 Markdown 渲染（工具气泡 / 确认卡片不渲染 md）
- **思考过程**：模型下发思考内容时**逐字实时展示**思考区（真流式，不是整块到达后假装流式），回答一开始即自动折叠为「已思考 N 秒」可展开条目；随历史持久化，刷新后仍可展开；模型不支持则不显示、不报错
- **回答逐字显示**：正文随生成逐字渲染，首字延迟明显低于「等整段生成完再显示」
- **空会话欢迎语**：一句带空间事实的问候，如「今天是你们在一起的第 N 天」（即时可得，不等待生成）

#### 2.2.3 过程呈现

- **一轮是一条时间流**：思考块、工具块、正文段按发生顺序依次出现；过程元素（思考、工具、已裁决确认卡）与对话元素（正文气泡、结果卡）分两层——过程块**无气泡壳**（灰底圆角容器或纯文字行），正文段沿用 AI 白气泡
- **进行中**：思考块**独立成行、流式展开**（标题行「思考 · 已思考 N 秒」+ 左侧 2px 竖线），工具调用逐条出人话状态行（灰底圆角 12px 容器，运行中带呼吸光晕，完成后归一为「✓ 动作 → 结果」）；结果卡**嵌在对应工具块容器内**（与工具行共享容器，卡片不浮在对话流里）
- **一轮结束后聚合**：多次工具调用聚合为一条「**已完成 N 步**」可展开摘要（展开看到的是每步人话状态，**不是技术细节**，审计仍归后台）；单步调用不聚合（一行比一条摘要更直接）
- **最终形态**：界面只剩结果卡 + 回答正文 + 思考与步骤两条折叠条目——过程不长期占据对话流
- **待确认期间确认卡展开置顶**（渐变描边带 + 操作按钮），裁决后（已执行 / 已取消 / 已过期）折叠为一行回执，与思考、工具行同层——确认卡也是过程，只是待确认那个窗口需要醒目

#### 2.2.4 卡片体系

- **操作确认卡片**（嵌入对话流）：预览为**目标形态**（发动态的卡片与发布前预览同形，不是参数表）+ 警告 → [确认执行] [取消] → 确认后变为已执行状态；参数校验前置，不合格的提案不出卡；卡片单次有效，15 分钟未处理自动过期（显示「已过期」，不可再确认）。待确认期间输入区仍可用（提案独立过期），但不能切换或删除当前会话
- **结果卡片**类型：记录列表 / 媒体网格 / 地点候选 / 媒体分组 / 单条详情 / 统计概览
  - 大段文字截断展示、点击展开
  - 媒体一律缩略图，点击开全屏查看器（复用传统模式同一查看器，**不跨模式跳转**）
- **列表卡计数与翻页**：显示**真实命中总数**与真实余量（如「共 320 条 · 还有 280 条」），并提供「再看几条」翻页（同一查询条件下推进偏移量，翻页结果照常可勾选）。语义检索无稳定总数时明确标注「按相关性截取，非全部命中」，不显示假总数
- **统计概览卡**：对话内的内容概览，由以下几块组成
  - **数字网格**：在一起天数 / 动态 / 媒体 / 相册 / 足迹与城市数 / 纪念日 / 互动
  - **分布摘要**：按年、城市各一行（「2024–2026 · 3 年共 498 条」「走过 5 城 · 杭州最多（18）」），不平铺明细——概览卡只给概览，逐年/逐城明细由 AI 另调对应查询（同下「不可勾选引用」）
  - **近 12 个月分布不上卡**，只给模型（仍能答「哪个月记得最多」），避免三组列表顶满对话流
  - **数字准且即时**：不是模型转述出来的
  - **不做图表**（折线 / 柱状 / 热力）
  - **不可勾选引用**：统计不指向具体记录，要展开某一维度由 AI 另调对应查询
  - **与后台仪表盘不重复**：仪表盘是 admin 监控面（含 AI 调用量 / 延迟 / 告警），本卡是对话内的内容概览
- **点赞 / 收藏 / 评论在 AI 侧是「设为」而不是「切换」**：说「点赞」就是设为已赞，重复说不会变成取消；**本来就已是该状态时不再出确认卡**，直接答复

#### 2.2.5 引用与操作范围

- **资源引用**：结果卡片内勾选 → 输入框上方引用条（可逐条移除）→ 随下一条消息提交，**仅当前会话内有效**（统计概览卡不参与勾选）
- **点选优先**：本轮消息带勾选时，**勾选范围就是操作范围**
  - 删除、移入 / 移出相册、评论、点赞收藏等作用于既有内容的操作，目标必须落在同类型的勾选集内
  - AI 想扩大范围（拿整份查询结果而不是你勾的那几条）时**服务端直接驳回、不出卡**，AI 在同一轮内按勾选范围重出，用户不会看到错卡
- **勾选的类型决定能做什么**：勾照片只能移入 / 移出相册，要删动态必须先查动态再勾动态（传统模式本就无「从相册删照片」操作，见「相册（独立底部 tab）」），AI 主动引导这一步而不是静默失败；单次批量上限 **50 条**，超出直接驳回并提示分批（不静默截断）
- **未勾选时**由 AI 判断，仍经确认卡逐条核对；不支持「勾 3 张、其中 1 张移 A 相册其余移 B」这类补集操作（需取消勾选后分两轮说）

#### 2.2.6 输入与运行控制

- **命令入口只有一个：输入区左侧的「+」**
  - 点开一个动作面板，**媒体与命令同屏可选**（命令项为：发动态 / 整理照片 / 查回忆 / 纪念日）
  - 选中后把结构化提示词模板填入输入框，用户可改可删再发送
  - **不提供 `/` 之类需要键盘触发的入口**：手机上打 `/` 要先切符号键盘，一步操作变成三步；桌面端也不为它保留第二套入口，避免「同一功能两条路径、行为不一致」
- **快捷指令 chips**（进首版，静态文案，点击填入输入框、不直接发送）：空会话时显示在欢迎语下方，用于回答「第一次来、不知道该说什么」；一旦有消息就不再显示（此后由「+」面板承担找命令的职责——**两者分工明确：chips 解决「不知道能做什么」，「+」解决「知道要做什么」**）
  - 文案原则：**只描述动作，不预设任何具体内容**——不写「上次去海边是什么时候」这类，因为空间可能根本没有相关记录，会让新用户觉得「这跟我没关系」。三条为：「帮我发动态」 / 「整理最近的照片」 / 「我们记过什么」
- **停止生成**：输入区右侧显示「停止 ■」按钮，可中止本次输出。中止即整轮回滚：用户消息、已产生内容、未裁决提案一并撤回，不留无下文的孤儿消息。**仅用户显式中止触发**；连接意外断开不删消息，保留已产生内容并标「已中断」
- **已中断消息可编辑重发**：「已中断」的用户消息下方悬浮两个裸图标（默认隐藏：桌面悬停该行显形，触屏点消息唤出）——「编辑」把原文回填输入框供修改后重发（不自动发送，原输入保留），该轮残局（用户消息、思考、工具步骤、待确认卡）一并回收不留痕；「复制」仅复制原文
- **多步任务不静默失败**：AI 按预算（轮次 / 工具调用数 / 墙钟）推进，读查询可并行；预算耗尽时必须给一个收尾回答并说清哪些没完成，不得一句不说就结束

#### 2.2.7 图片与「看图」边界

- **图只能跟着一次「发动态」走**：AI 模式没有「单独传一个文件」的场景，也没有「发张图给 AI 看看」这条路径——**媒体不入模型**，不做图片理解，AI 只知道「本条消息附带 N 个媒体（文件名）」；发图不给指令也无从处理，只会留下无处可用的闲置附件
- **入口收进【发动态】命令**：输入区不常驻独立的[附件]按钮
- **确认前什么都不发生**：选好的媒体在点「确认执行」之前，既不会出现在时间轴、也不会进相册；此时关掉或刷新就等于没发生过，要重来**重新选一次即可——原文件一直在设备上**
- **确认执行 = 提交**：上传时机与部分失败的处理与传统模式**同一条规则**（见「发布动态」「提交时才上传」）——全部就绪自动完成提交，个别失败不半发、单独重传，其余不重来
- **取消或过期不留痕迹**：不产生动态，也没有任何待清理的残留
- **要让 AI 处理已有图片**：走查询 → 结果卡勾选 → 引用，全程不需要看图
- 新照片只能随动态产生，不能直接进相册（相册媒体一律从动态时间轴中选取）

> 上传时机、临时区、媒体归属等**实现口径**见 ARCHITECTURE「媒体上传管线」与 AI模式设计「图片处理与存储」；本文只定义用户看到的行为。

#### 2.2.8 会话模型

- 多会话：左上角菜单抽屉管理会话列表（新建 / 切换 / 删除），单会话内持续滚动
- 会话按首条消息摘要自动命名；删除会话为**硬删**（聊天记录属过程性数据，不进回收站）
- **对话历史不设自动过期**：不做保留时长、不做定时清理——历史由用户自己掌握，删会话即删该会话的全部消息（硬删，不进回收站）。故**不存在「消息被清掉、只剩空会话壳」的状态**
- **不支持语音输入**：只用文字与「+」命令面板

#### 2.2.9 能力范围

AI 模式覆盖**业务数据操作与空间统计**：动态 / 相册 / 照片 / 地图 / 纪念日 / 互动 / 空间概览。

**系统配置、模型管理、账号、审计、回收站不设能力。**工具级定义见 AI模式设计「工具契约」。

| 能力 | 示例指令 |
|:---|:---|
| 发表动态 | 「帮我发一条动态，记录今天去看了电影」 |
| 评论 / 点赞收藏 | 「给 TA 刚发的那条动态点个赞」 |
| 管理相册 | 「把上个月去海边的照片整理到一个新相册」 |
| 整理相册内媒体 | 「海边相册里有哪些照片？」→「把第 3、5 张移出去」 |
| 查询历史 | 「我们第一次一起旅行是什么时候？」 |
| 空间概览 | 「我们一共记了多少条动态？」 / 「点亮了哪些城市？」 |
| 纪念日管理 | 「下个月纪念日提醒我提前三天」 |
| 足迹记录 | 「帮我把今天去的这家餐厅记到地图上」 |
| 删除内容 | 「把上周那三条动态都删了」（批量走一张卡一次确认） |

> **能力边界**：AI 模式对齐传统模式的**增数据 / 查数据 / 删数据**三面，扩展克制。传统模式能做的业务动作，AI 侧都有等价路径；传统模式的浏览态能力（滚动分页、总数展示）在 AI 侧以「真实总数 + 翻页」对齐。
>
> **不覆盖**：通知中心、设置页（含 AI 偏好自身的修改）、回收站、外观主题。

#### 2.2.10 设计原则

| 原则 | 说明 |
|:---|:---|
| 辅助而非替代 | AI 生成内容必须经用户确认 / 微调后才生效，不自动发布 |
| 纯对话，零配置 | 界面中不包含任何配置入口 |
| 操作必经确认 | 生成预览 → 发起人确认 → 生效（口径见 对外集成「工具权限分级与确认口径」） |

### 2.3 后台管理页面功能范围（admin）

登录：统一登录系统，**仅 admin 角色可登录**。

导航为扁平 7 项：仪表盘 / 空间管理 / AI 配置 / 外部集成 / 回收站 / 审计日志 / 服务日志（按管理对象分组，同类内容一处一事）。

- **仪表盘**：全站唯一监控入口——内容统计（单空间口径） / AI 调用量与 Token 消耗与平均延迟 / 最近活动 / 异常告警
- **空间管理**（管理对象 = 本空间，分 3 个 tab：空间信息 / 情侣成员 / 数据保留）
  - **空间信息**：名称 / 个性签名 / 在一起日期与在一起统计（同一张卡）
  - **情侣成员**：
    - **创建**：双方用户名 / 昵称 / 密码一次性提交；任一情侣角色已存在则拒绝
    - **建立后可改**：昵称、生日、头像、重置密码
    - **不可变更**：用户名 / 角色；**不提供删除**
    - admin 账号只读展示
  - **数据保留**：回收站保留期限（7~365 天，默认 30）——空间级保留策略集中于此，回收站页仅只读展示期限（对话历史不设保留期限，见「会话模型」）
- **AI 配置**（6 个 tab）
  - **供应商**：模型服务（名称 / 地址 / 密钥）的增删改；密钥只写不读
  - **对话模型链** / **嵌入模型链**：维护可用模型；**对话模型与语义检索模型分开配置**，同类可配多个并按顺序依次尝试。每个模型另可配**思考档位**（关 / 低 / 中 / 高，**默认关**）：开启后模型先思考再作答，**思考同样消耗 token（按所选供应商计费）**，由使用者按模型自行取舍。可选的档位由该模型**声明支持的档位**决定（不同模型能接受的档位不同，例如有些只有低 / 高）；现役模型关不掉思考，故「关」表示按该模型的最低档请求，而非完全不思考。另可配**上下文窗口**（该模型能容纳的上下文长度，决定 AI 能参考多长的历史对话）；不填则按默认值处理。部分供应商不支持配置思考档位，此时该项只读展示，不提供可改的控件
  - **提示词与风格**：全局提示词主干、输出风格库与全局默认
  - **MCP 工具**：内置工具启停
  - **访问令牌**：外部接入令牌的生成与吊销、只读或读写档位
- **外部集成**（2 个 tab）
  - **通知渠道**：空间级 Webhook 渠道配置、按事件订阅、预设模板、发送测试
  - **地图配置**：瓦片源卡片网格，公开 XYZ 或天地图密钥两种，可启用与删除、**不提供编辑**
- **回收站管理**（2 个 tab：已删除内容 / 操作日志）：查看已删除内容（按类型筛选、显示删除者） / 恢复（二次确认，支持批量） / 回收站操作日志（恢复 + 系统超期永久删除；保留期限提示只读展示）
- **审计日志**：AI 操作日志 / 外部 MCP 调用日志（PAT 来源）；模型响应延迟与用量报表归仪表盘，不在本页
- **服务日志**：实时查看服务端运行日志（级别 / 时间 / 消息 / 字段），可按级别与关键字筛选、可暂停跟随、可清空视图；**AI 调用失败的原因在此可见**（面向情侣用户只给可读文案，此处保留原始错误供管理员排障）。密钥类字段已打码；只保留最近的日志，更早的以部署侧输出为准
- **布局约定**：整页视口锁定（页面不滚动），各数据容器内部滚动、长列表表头固定；**同类多段内容用页内 tab 分区（侧栏保持扁平 7 项），一次只呈现一段**；操作反馈统一走全局 toast，危险操作用应用内确认对话框

> 页面实现与接口清单见 ARCHITECTURE「后台管理页面实现」。

## 三、体验规范

### 3.1 视觉与体验规范

#### 3.1.1 风格定调：iOS 原生 · 伴侣协作

| 风格 | 优势 | 劣势 | 适配度 |
|:---|:---|:---|:---|
| 可爱 | 年轻用户接受度高 | 容易幼稚化，男性用户可能排斥 | ★★★ |
| 浪漫 | 情感氛围强 | 视觉疲劳快，日常使用不够耐看 | ★★★ |
| **iOS 原生风格** | **熟悉顺手、久看不腻、男女通吃；毛玻璃 / 系统组件最贴合情侣日常记录** | 个性表达弱 | ★★★★★ |

> **核心感受**：以 iOS 原生语言承载——系统浅灰底 + 白色卡片 / 列表 + 暖粉主色 + 毛玻璃导航栏与 tab bar。不做强调「设计感」的定制主题，回归「这是一个认真做记录、每件事都顺手」的情侣 app：熟悉、温馨、好用。

#### 3.1.2 色彩体系（iOS 风格）

**设计定调**：
- 系统浅灰底 `#F2F2F7` + 白色表面 + 暖粉主色
- **暖粉**只用于着色点 / FAB / 选中；强调文字与图标用**深档粉**保证对比度
- **iOS 语义蓝**仅用于操作
- **危险红**仅用于破坏与未读

| 用途 | 浅色 | 深色 |
|:---|:---|:---|
| 背景 | #F2F2F7 | #000000 |
| 表面（卡片 / 列表） | #FFFFFF | #1C1C1E |
| 主色（着色点 / FAB / 选中） | #FF8FAB | #FF8FAB |
| 强调色（文字 / 图标） | #F06292 | #FFB4C2 |
| 操作色（iOS 蓝） | #007AFF | #0A84FF |
| 破坏 / 未读 | #FF3B30 | #FF453A |
| 正文 | #1C1C1E | #F2F2F7 |
| 次要文字 | #6C6C70 | #98989F |

> **强调色（暖色系预设，深浅各一套）**：

| 名称 | 浅色档 | 深色档 |
|:--|:--|:--|
| 柔雾粉 rose | #FF8FAB / #F06292 | #FF8FAB / #FFB4C2 |
| 蜜桃橙 peach | #FF9F7A / #E35F3D | #FF9D82 / #FFC4A6 |
| 落日金 gold | #F2B441 / #CF8A1C | #F2B441 / #FFD98B |
| 豆沙红 dousha | #E0786E / #B94D4D | #E0877F / #F0B0A9 |
> **对比度**：正文（#1C1C1E on #F2F2F7）≈15:1 满足 AA；**次要文字同属正文类，与正文一样要求 ≥4.5:1**（现值 #6C6C70 = 4.7:1）；主色 / 强调按 WCAG AA 使用（≥3:1 图标）。

#### 3.1.3 字体与排版（iOS 风格）

| 项目 | 规范 |
|:---|:---|
| 标题字体 | 系统字体 Semibold（-apple-system / PingFang SC），不引入装饰性衬线 |

#### 3.1.4 图标与插画

| 项目 | 规范 |

| 图标风格 | Lucide 线性图标，**描边随尺寸分档**：≤14px 用 2（极小徽标可至 2.2–2.5）；15–21px 用 1.8–2；≥22px 的大图标 / 占位 / 空态用 1.6–1.8。关闭、返回等操作类图标不受尺寸档限制（一律 2.5）。同一处不混用；界面禁 emoji |

#### 3.1.7 多设备响应式（三档）

单代码库纯 CSS 断点适配，无独立桌面版；iPhone 形态为基准，向上增强。**断点边界 = 768px / 1280px**（桌面门槛提到 1280 是为了让 iPad Pro 11 / 13″ 落在平板档）。

| 档位 | 视口宽度 | 布局 |
|:---|:---|:---|
| 手机 | < 768px | 底部 tab bar + 右下角 FAB，主壳最大宽度 480px 居中（基准形态） |
| 平板 | 768–1279px | **底部 tab 拉满视口宽度**；主壳 100% 宽无居中；内容区由各视图自管左右内边距；iPad Pro 全系归此档 |
| 桌面 | ≥ 1280px | **浮动圆角面板**（Stage Manager 风格）：主壳居中、宽 832px、四周留 16px 外距、圆角 18、白底 + 大阴影；body 渐变背景透出画布感；FAB 贴面板右下角 |

需求级约定：

- 主壳与独立整页（登录 / 通知 / AI 对话 / 设置）在桌面档统一走「浮动圆角面板」形态，且**尺寸完全一致**；**登录页在登录前后必须是同一个框**（含四边外距）
- 底部弹层在桌面档从面板**下边缘**升起；手机 / 平板仍贴屏幕底部（原生 sheet 手感）
- 全屏层（全屏查看器、相册「选择」页）在桌面档同样收进面板矩形，不铺满整个浏览器窗口
- 平板档各视图的左右内边距各自决定、不强制统一；照片墙与相册卡片等网格**按可用宽度自适应列数**（不出现横向滚动）
- 实现契约（令牌、组件、踩过的坑）见 客户端设计「响应式框架与浮层定位」

### 3.2 数据操作规则（用户可见行为）

#### 3.2.1 核心原则

> **只增不删（软删除），不可编辑，回收站兜底**
>
> **适用范围**：仅约束**记录内容**——动态、评论、相册、照片、纪念日条目、地图点位。
>
> **配置信息不受此限**——用户资料（头像 / 昵称 / 生日）、空间配置（空间名 / 空间签名 / 恋爱开始日期）均可随时修改（维护入口见「后台管理页面功能范围（admin）」）。
>
> **点赞与收藏是可撤销的关系数据**：取消即失效，不进入回收站，不属于记录内容。

| 操作 | 是否支持 | 说明 |
|:---|:---|:---|
| 添加 | 支持 | 创建动态 / 评论 / 相册 / 纪念日 / 地图点位 |
| 删除 | 支持 | 情侣双方均可软删除空间内任意记录内容（含对方发布）→ 进入回收站；删除对方发布的内容时向对方发站内通知（删除自己的内容静默） |
| 编辑 / 修改 | 记录内容不支持 | 动态 / 评论 / 相册 / 照片 / 纪念日 / 地图点位等不可二次编辑；配置信息可修改 |
| 恢复 | 支持 | 仅管理员可在后台管理页面从回收站恢复 |
| 永久删除 | 系统自动 | **回收站里的内容只在期限内存活**：到期后由系统自动**彻底删除、不可找回**（用户与 AI 都不可手动清理）。期限为空间级设置（7~365 天，默认 30），在后台「空间管理」维护、回收站页只读展示 |

#### 3.2.2 对各界面的影响

| 界面 | 变化 |
|:---|:---|
| 传统模式 | 详情页一律**无**「编辑」按钮；记录内容的删除入口统一为**长按条目**（不设常驻删除图标），确认动作一律写「移入回收站」（口径见 客户端设计「删除交互统一规范」） |
| AI 模式 | AI 回复中**无**「修改」选项；确认卡片仅有 [确认] [取消] |
| 后台管理 | 回收站管理模块 + 保留期限配置 |
