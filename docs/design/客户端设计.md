## 1. 客户端技术职责

### 1.1 两类客户端对比

| 维度 | 手机 APP | Web 端（服务端一体部署） |
|:---|:---|:---|
| **部署位置** | 用户手机，独立安装 | 服务端服务器，与后端同机/同集群 |
| **定位** | 个人日常使用主力终端 | 后台管理（系统配置 + 审计监控） |
| **包含内容** | 传统模式 + AI 对话模式 | 后台管理页面（Web 前台已取消，未来需要时另立需求） |
| **登录要求** | 需登录，登录页配置服务端地址，仅接受情侣角色（girl/boy） | 共用同一登录认证，仅接受 admin 角色 |
| **AI 能力** | AI 对话模式（全屏 Agent） | 仅模型/工具配置，无对话入口 |
| **与服务端关系** | 远程调用 REST API / MCP | 本地/内网调用，同进程或同集群 |
| **更新方式** | 自签名 APK 直接分发手动安装（无版本管理设施），Android only | 服务端统一部署更新 |

### 1.2 手机 APP 职责

| 职责 | 说明 |
|:---|:---|
| 渲染两套界面 | 传统模式 + AI 对话窗口 |
| 调用后台接口 | REST API（手动）+ AI 对话接口（自然语言代理操作） |
| 本地缓存 | 对话历史缓存、图片缩略图等（对话历史以服务端为权威存储，本地仅缓存加速） |
| 用户认证 | Token 管理、自动刷新 |
| 页面跳转契约 | 内容类跳转统一「跳列表页并定位高亮该条」，不新增详情页：动态入口走 `/posts?focus=<id>`、纪念日走 `/anniversaries?focus=<id>`（通知 / 首页回忆卡 / 相册「查看所属动态」同一做法；地图点位同思路） |
| 首页回忆精选取数 | 由服务端在**全量历史池**随机取，客户端不自取最新一页再洗牌（否则更早的历史永远抽不到）：`GET /posts?sample=1&page_size=N`；**分层取两批**——`media=1` 供封面卡、`media=0` 供文字回忆，保证「有图那层」非空，封面卡才真正常驻（PRODUCT「首页」） |
| **不做的事** | 不存 API Key / 不配模型 / 不注册工具 / 不调第三方模型 |

> 客户端代码中**没有任何模型相关配置**，只有一个后台服务的 base URL。

## 2. 删除交互统一规范

> 前提是「两个人用、以展示为主、删除很少」：常驻删除图标既是视觉噪音又易误触，故动态 / 相册 / 纪念日 / 足迹四处统一为一套手势 + 一套文案，不做各自的行内入口。

### 2.1 三条原则

1. **列表即入口**：删除不做常驻图标——列表 / 网格卡片长按 500ms 触发；详情页不再放任何删除入口（动态详情页整体移除，见 PRODUCT「动态」）。
2. **一次确认**：统一走底部 `ConfirmSheet`（标题 + 后果说明 + [取消] [移入回收站]），没有二次确认，也没有直接删除。
3. **手势要教一次**：长按是隐形手势，每个列表页**首次进入**用 toast 提示一次（`localStorage` 标记，`utils/storage.ts#onceHint`），之后不再打扰。

长按与子元素动作不冲突：按钮 / 输入框 / 视频等交互元素上 `@pointerdown.stop`，且长按触发的 `click` 被吞掉（`useLongPress` 在 `pressing` 期间 `preventDefault`），按住期间条目给 `pressing` 背景反馈。

### 2.2 各界面口径

| 界面 | 入口 | 确认动作 | 后果文案 |
|:---|:---|:---|:---|
| 动态（时间轴卡片） | 长按卡片 | 移入回收站 | 动态里的照片与评论会一并移入回收站。 |
| 评论（展开的评论行） | 长按评论行 | 移入回收站 | — |
| 相册（集合列表卡片） | 长按卡片 | 移入回收站 | 有内容时补「照片本身不受影响（回到未归属状态）。」 |
| 相册详情（照片格） | 长按照片 | 移出当前相册 | 只是移出相册，照片本身不会删除（仍在时间轴）。**非破坏性，确认按钮不用危险色** |
| 纪念日（卡片） | 长按卡片 | 移入回收站 | — |
| 足迹（列表行） | 长按列表行 | 移入回收站 | 动态里的地点名仍保留为快照。 |

- 统一收尾：`把「{名称}」移入回收站？{后果}想恢复的话，到后台回收站里找回。`；删除**对方发布**的内容再补一句「对方会收到一条通知。」（自删静默）。
- 成功提示：`已移入回收站` / `已移出相册`；删除后就地移除该条，不整表重载（避免闪烁与滚动位置丢失）。
- 文案单一来源 `app/src/utils/deleteCopy.ts`；手势 `app/src/composables/useLongPress.ts`（500ms、位移 >8px 取消、抬起 / 离开 / 取消均撤销）。短按语义不变：卡片进详情、足迹行居中该点位。

### 2.3 接口约定：删除一律 204

删除接口返回 **204 No Content**。客户端 `api()` 必须容忍 204 / 空响应体，否则「删除其实成功了，但前端抛 `Unexpected end of JSON input`」——表现为报错 toast + 列表留着旧数据。

## 3. 媒体另存到本机

全屏查看器底栏的「保存」（照片 / 视频 / 音频同一入口）。需求口径见 PRODUCT「动态」「设置」。

### 3.1 边界

- **单条保存**：只保存当前这一条；无批量选择、无「保存全部」、无保存通知。
- **不是导出 / 备份**：平台不内置备份/导出/导入（见 ARCHITECTURE「备份与迁移」）；「保存」只是把眼前这条另存到本机。
- 保存的是**原始文件**：服务端直发 `m.file_path`，不转码、不压缩、不剥 EXIF。

### 3.2 手机优先：系统「另存为」（Android SAF）

- 原生环境（Android APK / iOS / 桌面 Tauri）走 `dialog.save()`：Android 即 SAF `ACTION_CREATE_DOCUMENT` —— **零存储权限**、用户自选去处（相册 / 下载 / 文件管理器）、重名自动加后缀。
- 选定路径后**按块流式写入**（`fs.open` → `write(chunk)` → `close`），大视频不进内存；`open` 不可用时退回 `writeFile` 一次性写。
- 取消另存为 → 静默结束，**不下载任何字节**。
- 前端经 `window.__TAURI__` 调用插件，APP 侧不引入额外 npm 依赖；Rust 侧注册 `tauri-plugin-dialog` / `tauri-plugin-fs`，权限 `dialog:allow-save` + `fs:allow-write-file`。

### 3.3 文件名：服务端为准，客户端同规则兜底

- `GET /api/v1/media/file/{id}?v=raw&download=1` 时服务端补 `Content-Disposition`：`{YYYY-MM-DD}_{照片|视频|录音}_{序号}.{ext}`；日期取 `taken_at` → 动态 `created_at` → 媒体入库时间，序号 = 该动态内媒体顺序。
- 中文走 RFC 5987 `filename*=UTF-8''…`：跨域时 `<a download>` 的自定义名会被浏览器忽略，只有响应头算数。CORS 需 `Access-Control-Expose-Headers: Content-Disposition`（并允许 `Range`）。
- 客户端 `utils/saveMedia.ts` 的 `mediaFileName()` 与服务端同规则，作为探测失败时的兜底名。兜底口径：
  - **序号**：只有 `mode='post'` 的查看器（items 就是该动态的媒体）才传动态内下标；时间轴 / 相册模式的 items 是查看器自己的列表，下标**不能**冒充动态内序号 → 留空，兜底用媒体 id。绝不拿「查看器索引 + 1」当序号。
  - **扩展名**：优先取媒体 URL 上的 `?ext=`，没有才退回词表。
- 词表（照片 / 视频 / 录音、兜底扩展名）只有一份：`app/src/utils/mediaKind.ts`，客户端组件与 mock 都 import 它，避免三处手抄抄出契约漂移。

### 3.4 签名与重签

媒体直链是 15 分钟 HMAC 签名。保存时若签名已过期（401 / 403），客户端 `refreshMediaUrl(ids)`（`POST /api/v1/media/reurl`，体带 id 列表、一次换多条）重试一次；仍失败 → 提示「保存失败，请检查网络后重试」。页面停留期间的静默重签为 5 分钟一轮。

### 3.5 Web / 无 Tauri 降级

1. 先探测 `GET …&download=1` + `Range: bytes=0-0`（只取 1 字节）：拿到 `Content-Disposition` → 把带 `download=1` 的直链交给浏览器下载管理器（流式、可续传、文件名由服务端给）。
2. 探测失败（老服务端 / 跨域头缺失）→ `fetch` 取字节 → blob → `<a download>` 兜底，文件名用客户端规则。

> 真机侧待验项见 DEVELOPMENT「发布前检查清单」。契约的自动守卫是 `server/internal/api/media_download_test.go`：文件名与 RFC 5987 形态、不带参数不出头、CORS 暴露头、Range → 206 / 越界 416。mock 与服务端同口径（按 kind 给真实小字节、download 头、Range）；两项「探测失败兜底 / 取消不下载」无自动覆盖，改动这两条时手工过一遍。

## 4. 响应式框架与浮层定位

> 需求侧口径见 PRODUCT「多设备响应式（三档）」；本章只讲实现契约，避免「每个浮层各写一套定位」。

### 4.1 页面外壳 `PageLayout`

所有页面（含一级 tab、二级详情/表单、独立整页）的**页面内层结构**统一走本组件：navbar（glass、标题居中、可选返回/右上操作）+ 内容区（列宽/内边距/滚动/安全区）。外层桌面浮窗（`MainView .main` / `App .page-col`）仍由外壳负责，本组件只管内层。

| props | 默认 | 含义 |
|:---|:---|:---|
| `title` | 必填 | navbar 标题 |
| `back` | `false` | 显示返回键（动作由页面通过 `@back` 决定：列表/详情 `router.back()`、表单 `closeForm()`） |
| `actions` | `false` | 显示 `NavActions`（通知+设置；AI 页用 `#nav-right` 自行放 `NavActions :show-bell="false"`） |
| `scroll` | `true` | `false` 时内容区 `overflow: hidden` + flex 列（地图/对话等「填充不滚动」页）；可为动态绑定 |
| `standalone` | `false` | 独立整页（通知/设置/对话）：套 `.page-col` 浮动卡片框架 |

插槽：默认（内容区）、`subheader`（navbar 下、内容区外的固定条，如相册/地图的 seg 切换）、`nav-right`（navbar 右侧，与 `actions` 可叠加）、`footer`（内容区外底部固定条，如对话输入栏）。

**整页底色钩子 `--page-bg`**：页面经 class 向 PageLayout 根注入（如 AI 对话页注入 `var(--ai-bg)`）；未注入时移动/平板档 transparent、桌面档卡片回落 `var(--surface)`。

**统一空态 `EmptyState`**（口径见 PRODUCT「图标与插画」）：图标 + 短标题 + 可选副文案 + 可选 CTA。页面级空态直接用（52vh 最小高度垂直居中）；小容器（Sheet、地图覆盖层等）传 `compact`。各页不得再手写空态。

约定：

- **横向 padding 只归 PageLayout**：`--side-pad` 由 `.page-body` 消费，页面内部容器**不得再写横向 padding**（否则与外壳叠加，手机档被挤窄）；页面自有内容用 `padding: Npx 0`。
- **`box-sizing`**：`.page-body` 同时有 `width: 100%` 与 `padding-inline`，必须 `border-box`（见「坑与验收口径（改浮层前先看这里）」坑 1）。
- **`.navbar` 布局只在 PageLayout 定义且是 `scoped`**：页面内若自建 navbar，要么复用 `PageLayout`，要么在文件内补回布局，不能只写 `class="navbar glass"` 就指望全局样式。
- **标题居中靠全局 `.navbar .title`**（`App.vue`，绝对定位 + `translateX(-50%)`）：这条规则是承重的，删除会让所有页面标题贴左。
- **KeepAlive 滚动约定**：内容区在 `onActivated` 内**同步**写回离开前的 `scrollTop`（不要 `nextTick`），同帧写回可避免两帧跳动。
- **TabBar / FAB 可见性**：一级 tab 有 TabBar + FAB（由 `MainView` 提供）；整页表单/详情（`chromeHidden`）隐藏；独立整页（`/login`、`/notifications`、`/chat`、`/settings`）在 `MainView` 之外，天然无底栏。
- **唯一例外 `LoginView`**：登录页无 navbar 且需要「可滚动 + 内容垂直居中」，而 `scroll=false` 是 `overflow: hidden` 做不到「内容高于视口时可滚、不裁顶」，因此自持页面容器。但横向 padding **必须走 `--side-pad`**——例外只豁免外壳结构，不豁免令牌。桌面档卡片与其它独立整页一致，满足「登录前后同一个框」。

### 4.2 框架令牌（`App.vue` 唯一定义）

| 令牌 | 手机 <768px | 平板 768–1279px | 桌面 ≥1280px | 用途 |
|:---|:---|:---|:---|:---|
| `--frame-max` | 480px | 100% | 832px | 外壳 / 独立整页的宽度上限 |
| `--frame-inset` | 0 | 0 | 16px | 卡片与视口的外距（上下左右同值） |
| `--frame-radius` | 0 | 0 | 18px | 卡片圆角 |
| `--frame-shadow` | none | none | 大阴影 | 卡片阴影 |
| `--col-max` | 480px | 100% | 720px | 内容列宽度（外壳内部的第二层） |

消费方只有两处：`MainView .main`（登录后的外壳）与 `App .page-col`（登录 / 通知 / 设置 / AI 对话等独立整页）。**新页面一律套 `.page-col`**，不要再自己写宽度、高度、圆角与阴影——桌面档的卡片尺寸只允许有一个来源。

### 4.3 浮层定位约定

| 浮层 | 手机 / 平板 | 桌面 |
|:---|:---|:---|
| 底部弹层 `Sheet.vue`（`ConfirmSheet` 等全部实用弹层都走它） | 贴屏幕底、`min(420px, 100%)` 宽，遮罩铺满整屏 | 贴**面板下边缘**：弹窗 `width: min(var(--frame-max), calc(100% - 2 * var(--frame-inset)))`、四角 18；**着色遮罩只覆盖面板矩形**（`mask` 仍铺满视口，暗色由 `::before` 画、`pointer-events: none`，因此「点面板外空白也能关闭」的手感不变）；标题 / 正文 / 按钮限宽 520px 居中 |
| 全屏查看器 `MediaViewer` | `inset: 0` 铺满 | 面板矩形：`top/bottom: var(--frame-inset)`、左右居中且同宽、同圆角 |
| 相册「选择」页覆盖层 | `inset: 0` 铺满 | 同上，收进面板矩形 |
| toast `AppToast` | 视口水平居中 | 不用改：面板本身就居中，视口居中即面板居中 |

### 4.4 坑与验收口径（改浮层前先看这里）

1. **`box-sizing`**：只写 `width` 而默认 `content-box` → 加上 16px 内边距后弹窗比屏幕 / 面板**宽出 32px**（手机贴边溢出、桌面探出面板）。**同类坑复发过一次**：`.page-body` 同时写 `width: 100%` 与 `padding-inline` 而漏了 `box-sizing`，手机档整页比视口宽 32px，10 个页面全中；桌面档因 `--side-pad: 0px` 反而看不出来。**凡「width + padding」同时出现，必须显式 `border-box`。**
2. **scoped 样式优先级**：各页 scoped 的 `height: 100%`（0,2,0）会压过全局 `.page-col`（0,1,0）→ 桌面档卡片被撑到贴住视口下边缘、只剩上外距。桌面档规则用 `.page-col.page-col.page-col`（0,3,0）压过去。
3. **元素 `opacity` 会连带子元素**：「取消」按钮写 `background: var(--muted-ink); opacity: .12` → 文字跟着变淡，读起来像禁用态。压背景请用 `var(--sk)`（半透明灰），不要用 `opacity`。

底栏 / 底栏类横向操作的排版同理：**横排元素别把提示挤成窄条**——窄屏下提示会逐字换行，看着像错乱（需求侧的「按钮与提示各占一行」见 PRODUCT「动态」）。

**验收口径**（改浮层后按这六档跑浏览器实测，比对 `.main` 与 `.page-col` 的 x / width / top / height / bottom / radius / shadow）：390×844、834×1112、1024×768、1280×800、1440×900、1920×1080 六档逐字段一致；桌面档弹层 rect == 面板 rect；手机档弹层贴屏幕底且不溢出 32px。

**环境坑**：Vite dev server 偶发不感知外部写入（改动在硬盘上、dev server 仍返回旧 CSS 模块），`touch` 该文件即可触发失效；排查方式是直接 `curl` 该 SFC 的 `?vue&type=style` 子请求比对。

## 5. 媒体查看器

> 需求口径见 PRODUCT「动态」「相册（独立底部 tab）」。组件只有一个：`app/src/components/MediaViewer.vue`，时间轴 / 动态 / 相册三处共用（AI 模式的结果卡也复用它，不跨模式跳转）。

### 5.1 三类分支

| kind | 呈现 | 交互 |
|:---|:---|:---|
| `photo` | `.mv-img`（原生尺寸 + `max-width/height: 100%`） | 双击 / 滚轮 / 捏合缩放，放大后可拖动，左右滑动切条 |
| `video` | `.mv-video`（`controls playsinline`）+ 居中 `.mv-play` 播放按钮 | 点按钮播放；播放中按钮隐去；点画面暂停 / 继续；播完复位 |
| `audio` | `.mv-audio` 卡片：封面 + 「录音」+ 日期 / 时长 + 播放按钮 + 原生 `<audio controls>` | 按钮播放 / 暂停；原生控制条负责进度、音量、倍速 |

顶部 `.mv-kind` 类型标识（图标 + 照片 / 视频 / 录音）与计数器同排，三种类型一眼可辨。

### 5.2 为什么「点了才播」而不是自动播放

带声音的 `autoplay` 会被浏览器拦截（未手势时实测 `paused: true, readyState: 0`，等于进了详情什么都不动），静音自动播放又要再做一层「点击取消静音」。**点击就是用户手势**，可以直接出声，与 iOS 照片 App 的心智一致。

### 5.3 状态管理

- `playing`（按钮显隐 / 图标）、`failed`（兜底文案）、`mediaDuration`（`loadedmetadata` 取真实时长，回退到接口 `duration`）全部由播放器元素的事件驱动。
- `go()` 切条、`close()` 关闭都先 `pause()` 上一条（`stopMedia()`），避免「换了一张图，背景还在响」。
- `error` 事件 → `.mv-fail` 卡片：说明文件可能损坏或格式不受支持，并引导先「保存」到本机；此时播放按钮隐藏，底栏「保存」仍在。
- 底栏提示按类型换文案（文案内容见 PRODUCT「动态」的全屏查看器约定）；此处只保证三种 kind 各自注入对应文案。

### 5.4 四种模式（mode）与序号口径

| mode | 谁在用 | 动态内序号 | 归属类入口（查看动态 / 移出相册） |
|:---|:---|:---|:---|
| `post` | 动态卡片（items 就是该动态的全部媒体） | 取 `查看器下标 + 1` | 渲染 |
| `timeline` / `album` | 时间轴 / 相册详情 | 留空 | 渲染 |
| `single` | **AI 模式的结果卡**（单条记录，不属于某个动态的全部媒体） | 留空 | 不渲染 |

**序号只由 `post` 模式给出**：其余模式的下标只是查看器自己的位置，拿去命名会得到错误序号（AI 单条卡恒为 1）。序号留空时另存文件名回退到**媒体 id**（口径见「文件名：服务端为准，客户端同规则兜底」），故 `single` 也让 AI 卡不出现归属类入口。

### 5.4 离线样本（tools/mock）

> `tools/mock` 是**离线开发辅助**（无后端时调界面用），不是契约基准——契约以 `server/` 实现与本文档为准，定位见 DEVELOPMENT「本地开发（浏览器为主）」。

`tools/mock/fixtures/` 存真实可播样本，`routes.mjs` 按 kind 下发（文件缺失时退回内联占位字节，保证 mock 永远能起）：photo `sample-photo.jpg`（1200×800 JPEG，Pillow 画渐变）/ video `sample-video.webm`（640×360 VP8，Chrome `MediaRecorder` 录 canvas 3s）/ audio `sample-audio.wav`（8kHz 单声道 3s，python `wave` 正弦音）。

**视频为什么是 WebM**：开发机没有 ffmpeg、也没有外网，只能在浏览器里录一段真视频。播放器代码路径与真实 H.264 / MP4 完全一致，**对外契约仍以服务端为准**（服务端下发 MP4）。`fixtures.mjs` 的 `ext` 与样本字节对齐（photo→`jpg`、video→`webm`、audio→`wav`），另存文件名随之变化；客户端兜底命名读 URL 的 `?ext=`，所以两边扩展名始终一致（口径见「文件名：服务端为准，客户端同规则兜底」）。

> 验收口径（浏览器实测，真实 mock）：时间轴走到三类条目，标识分别为照片 / 视频 / 录音（对应 5.1 顶部 `.mv-kind`）；点播放后视频与录音进入播放态；切条后仍在播放的媒体数 1 → 0（对应 5.3 `stopMedia`）；把 `src` 换成坏数据 → `.mv-fail` 出现且播放按钮隐藏（对应 5.3 `error` 分支）。样本的容器头与另存扩展名由 mock fixtures 自包含 + `media_download_test.go` 守卫（见「媒体另存到本机」）。
