## 1. 产品概述

### 1.1 产品定位

一款面向**单一情侣**的**生活记录与情感管理应用**，帮助情侣双方共同记录日常、管理回忆、追踪足迹、维护纪念日，并通过 AI 智能助手降低使用门槛。

> **产品形态**：自部署、自用——以自部署软件形态发布（服务端二进制 / Android APK / Docker 镜像），服务运行在部署者自己的服务器（NAS/VPS），部署与运维方式（TLS/反代、进程管理、备份）由部署者自选。非多租户 SaaS，无应用商店上架与合规负担，无第三方接入审批流程。

### 1.2 产品组成

| 组件 | 定位 | 部署位置 |
|:---|:---|:---|
| **手机 APP** | 个人日常使用主力终端，双模式界面（传统 + AI 对话） | 用户手机，独立安装 |
| **Web 端（后台管理页面）** | 系统配置、模型管理、审计监控 | 与服务端同机/同集群部署 |
| **后端服务** | REST API + MCP Server + 模型网关 + 业务逻辑 + 数据存储 | 自部署服务器（NAS/VPS） |

### 1.3 核心理念

- **传统模式**：完整的、可手动操作的情侣生活记录 APP
- **AI 模式**：独立的全屏对话窗口，所有功能通过自然语言对话完成
- **两套逻辑并行**，互不干扰，共享同一套底层数据与业务服务
- **数据操作原则**：只增不删（软删除），记录内容不可编辑，回收站兜底；配置信息（用户资料/空间配置）可修改

## 2. 角色与账号

| 维度 | 说明 |
|:---|:---|
| 账号体系 | 部署时通过环境变量内置 admin 账号，无注册逻辑 |
| 冷启动 | 部署 → admin 登录 → 添加情侣信息（girl/boy） |
| 角色 | admin（部署者）/ girl（女方）/ boy（男方） |
| 权限分层 | admin 拥有系统配置权（模型/MCP/回收站/审计）；情侣用户专注内容操作 |
| 密码重置 | girl/boy 忘记密码由 admin 在后台管理页面重置（无自助找回，不依赖外部邮件/短信服务） |
| 登录入口 | APP / Web 后台共用同一登录系统 |
| 未登录状态 | 所有页面重定向至登录页，无公开匿名访问 |

> **核心原则**：用户侧客户端仅手机 APP 一种形态（Web 前台已取消，未来需要时另立需求）；Web 后台管理页面面向 admin。
> 认证机制（JWT + Refresh Token / PAT）见 DESIGN.md《统一登录与认证》。

## 3. 双模式界面

### 3.1 双模式对比

| 维度 | 传统模式 | AI 模式 |
|:---|:---|:---|
| 交互方式 | 点击、滑动、表单填写 | 自然语言对话 |
| 操作粒度 | 用户手动完成每一步 | AI 理解意图，批量执行 |
| 适用场景 | 精细操作、浏览回顾 | 快速记录、批量整理、模糊查询 |
| 学习成本 | 需理解页面结构 | 只需会说话 |
| 确认机制 | 操作即生效 | AI 生成预览，用户确认后生效 |
| 数据权限 | 用户直接操作 | AI 以用户身份代理操作（JWT），写操作需发起人确认 |

### 3.2 模式切换

- 切换入口：**设置页**切换传统模式 / AI 模式
- 两种模式互相独立：
  - 传统模式：展示为主，按钮简洁，删除等操作不干扰视觉体验
  - AI 模式：支持文字/图片输入（语音见路线图），确认卡片/图片展示/图表展示等丰富交互
  - AI 可用性：服务端未配置模型 Key 时，AI 模式切换项置灰并提示（无 Key 即不可用，后台不设独立开关）
- AI 模式内直接展示结果，**不做跨模式跳转**
- 状态保持：
  - 传统模式：记住上次浏览位置
  - AI 模式：对话历史服务端持久化（按保留时长清理），本地仅缓存，跨设备不丢失

### 3.3 切换动效

- 进入 AI 模式：轻柔淡入（与 6.5 动效规范一致），背景轻微暗化
- 退出 AI 模式：轻柔淡出，背景恢复

> AI 对话的端到端调用流程（含确认卡片协议）见 DESIGN.md《MCP 统一调用机制》。

## 4. 传统模式 — 页面与功能

**底部导航（五个 tab）**：首页 / 动态 / 相册 / 纪念日 / 地图；另设**右下角浮动添加按钮（FAB，添加菜单）**：记动态 / 添加地点 / 纪念日 / 相册（无独立「传媒体/传照片」入口）。

- 通知 / 设置入口：仅在一级 tab 页（首页/动态/相册/纪念日/地图）右上角显示通知铃铛 + 设置图标；AI 对话页仅显示设置图标；通知/设置/发布/详情等二级页不显示（见 4.8）

### 4.1 首页（纯情感仪表盘）

- **顶部：关系状态栏（情感展示）**
  - 双方头像 & 昵称
  - 在一起天数
  - 下一个纪念日倒计时
  - 右上角：通知铃铛（红点，进入通知中心）+ 设置图标（进入设置页）
- **中部：卡片区**
  - 回忆精选：从历史照片/动态池随机抽取，常驻兜底卡（每次进入可刷新），保证首页永不空态
  - 那年今日：同月同日历史回忆入口卡（显示篇数，有数据才出现）
  - 全新部署无任何数据时：插画风空态（暖色渐变卡片 + 图标组合，不引入图片资产）+ 引导创建第一条内容
- **底部：无添加入口**（所有添加统一走右下角 FAB，含快捷创建纪念日/动态，复用现有能力）
- **发布动态**：右下角浮动添加按钮（FAB）→ 记动态（媒体随动态）

> 提醒类内容（新动态提醒 / 足迹更新 / 相册上新）不再以卡片形式出现在首页，统一收敛至通知中心（见 4.8）。
>
> 「写封信」「许个愿」列入后续版本路线图，首版不实现：当前无信件/愿望的实体、页面与工具设计，待专项设计后再进正式范围。

### 4.2 动态

> 「动态」为底部导航 tab 之一（动态列表）；相册为独立底部 tab（见 4.5），不挂在「动态」内。

- **中部：动态列表**
  - 按时间倒序展示所有动态
  - 滚动加载：滚动接近底部时自动拉取下一页（页头不设刷新按钮）
  - 动态卡片（文字/媒体/地点/心情/点赞/收藏/评论数）
  - 卡片内完成全部操作：点媒体进全屏查看器（照片可缩放、视频/音频点击播放，多张可左右切换，「保存」到本机）、点赞/收藏、展开评论列表与发表评论
  - **不设动态详情页**（2026-09-10 决定）：卡片已展示全文与全部媒体，独立详情页冗余，移除；
    通知 / 首页回忆卡 / 相册「查看所属动态」等入口改为跳时间轴并定位高亮该条（`/posts?focus=<id>`，与地图点位同做法）

### 4.3 发布动态

> 移除独立「传媒体」入口，媒体只随动态存在（删除动态即删除其媒体，见 4.5）。

- **正文**：文字（可选，可留空只传媒体）
- **媒体**：图片/视频/音频多选（可选）；以方格网格预览，最后一个格子为「+」，支持连续追加；点选 X 移除单张
- **附加信息**：
  - 地点（可选）：输入地名 → 后端地理编码 API 返回候选列表；无满意结果时可在内置迷你地图上点选取坐标（见 4.4）
  - 心情标签（可选）：温馨系预设 + 自定义输入
- **发布条件**：正文 / 媒体 / 地点 / 心情 至少一项（不允许空动态）
- 操作：[发布]（不提供草稿功能）

### 4.4 地图

- **顶部：视图切换**
  - 地图视图（默认）
  - 列表视图（管理所有点位）
- **中部：足迹展示**
  - 地图视图：显示所有地点点位
  - 列表视图：查看点位 / 删除点位（软删除进回收站）
> **地理编码**：`GET client/api/v1/geocode?q=<地名>` 返回候选列表（名称/城市/经纬度/描述文案）；候选都不满意时支持「地图选点」兜底——在迷你地图上点选直接取得坐标（mock 先行，真实后端见 docs/TODO.md）。
> **添加地点（表单页）**：FAB「添加地点」→ 完整表单页（名称 + 搜索候选回填 / 地图选点 / 手动经纬度 + 保存）。
> **点位来源**：双来源进同一点位池——① 动态带地点时自动同步生成（地点名相同则复用已有点位，坐标以先创建者为准；不做邻近坐标合并）；②手动创建（地图页表单、AI 口语报点 create_map_point）。
> 地图瓦片服务地址可配置（见 DESIGN.md 4.7 地图服务）。

### 4.5 相册（独立底部 tab）

> 相册为独立底部 tab（见底部导航）；创建通过全局 FAB「相册」→ 自动弹出创建 Sheet。

- **顶部：视图切换**
  - 时间轴视图（默认）
  - 集合视图（手动相册）
- **中部：内容展示**
  - 时间轴视图：所有照片/视频/录音按时间排列（三类进同一个全屏查看器）
  - 集合视图：展示所有相册封面
- **底部**：无添加入口（创建走全局 FAB「相册」）

> **媒体来源模型**：媒体不再独立存在——所有媒体随动态发布进入时间轴，**删除媒体 = 删除整条动态**（时间轴/集合内均无独立媒体删除按钮；历史已存在的独立媒体仍兼容展示与移入相册，但不可再新创建，后端独立媒体接口 410）。相册内仅支持「移出当前相册」（媒体回到未归属状态，不删除，仍在时间轴）。
> **相册归属规则**：一个文件只能归属一个手动相册（全相册唯一）；已归属的文件不能再加入其他手动相册（选图器置灰并显示所属相册名）。
> **收藏进集合**：时间轴视图支持多选 → 「加入相册」（选择已有相册或新建并加入）；已归属媒体重复加入时后端 409 并提示。
> **相册详情添加入口**：手动相册内照片网格末尾为「+」格子（最后一个图片图标）；点击打开与时间轴 tab 视觉一致的按月分组选择页，已归属本相册/其他手动相册的媒体灰显禁止选择（tag 显示「已在本相册」或所属相册名），未归属媒体多选后「加入相册」（重复归属后端 409 兜底）。

### 4.6 纪念日

- **中部：纪念日列表**
  - 展示所有纪念日（名称/日期/倒计时），全部按年重复循环（无一次性纪念日）
  - 每个卡片支持删除（移入回收站，不可编辑）
- **添加与管理入口**
  - 添加入口：右下角 FAB → 纪念日；页头与空态均不设添加按钮
  - 添加为完整表单页：标题 + （阳历 / 农历）切换 + 日期
    - 阳历：直接选择公历日期
    - 农历：选择 农历月/日（可勾选闰月），实时显示对应公历日期（内置离线换算 1900–2100 表驱动，全区间校准见 docs/TODO.md）
  - **服务端契约（真实化，A3）**：`date` 一律 `YYYY-MM-DD` + `type ∈ {solar, lunar}`；lunar 时 `date` 为**农历日期**（如 `1996-05-15` = 农历 1996 年五月十五），不存 lunar_month/lunar_day 冗余；闰月语义由 `is_leap` 标记承载（true=闰月，缺省=平月）；倒计时与 `/space` 的 `next_anniversary` 公历展示由服务端以内置离线换算（`server/internal/lunar`，与客户端同源同表）推算下一次公历。
  - [提醒设置]：每个纪念日配置提前提醒天数（默认 1 天）；提醒同时进通知中心与已配置的外部渠道（站内+外部同发）

### 4.7 设置

> 入口：一级 tab 页右上角设置图标（AI 对话页右上角仅设置、登录页除外）；本页为纯设置页，不含任何内容浏览或快捷跳转。
> 资料与空间类配置（我的资料/情侣空间信息）不在 APP 设置页，统一由后台管理页面维护（见 8.3 空间管理），APP 只做业务数据管理。**AI 偏好（输出风格、对话保留时长）属个人体验项，保留在 APP 设置页**（见下方「AI 偏好」）。

- **AI 模式**
  - 进入 AI 模式（独立全屏对话窗口）；后台未配置模型 Key 时置灰并提示原因
- **AI 偏好**（个人体验项，仅该用户发起 AI 会话生效）
  - 输出风格：文艺 / 幽默 / 简洁
  - 对话历史保留时长：7 / 30 / 90 天 / 永久（默认 30 天）
- **外观**
  - 深浅模式（跟随系统 / 浅色 / 深色）
  - 强调色（暖色系预设色板）
- **其他**
  - 关于（版本号 / 服务端地址 / 项目主页）
  - 退出登录

> AI 操作记录不在 APP 展示——审计（含 AI 操作日志）统一归后台管理页面「审计日志」（见 8.3）。

> **注意**：
> - 设置页中不包含任何模型配置项（API Key、模型选择、自定义端点等），这些全部由后台服务管理。
> - 设置页**不含回收站入口**——回收站仅后台管理页面可见可操作（见第 7 章）。
> - 外观基于设计令牌（CSS 变量）实现，首版提供深浅模式+强调色；令牌化架构天然支持未来扩展多套主题。

### 4.8 通知中心

- **入口**：通知+设置按钮仅在一级 tab 页（首页/动态/相册/纪念日/地图）顶部右上角显示；AI 对话页仅显示设置按钮（不含通知铃铛）；通知/设置/发布/详情等二级页面不显示（仅一级 tab 页 + AI 页仅设置）
- **内容**：通知列表按时间倒序——新动态 / 点赞 / 评论 / 收藏 / 足迹更新（手动建点或 AI 口语报点时报另一方；动态带地点自动生成的点位不另发，随该条动态的「新动态」）/ 纪念日提醒 / 相册上新（对方创建手动相册时，含 AI 代建；自建静默，仅站内——外部推送口径见 8.1）/ 内容删除（仅当对方删除你发布的内容时产生；删除自己的内容静默。**按内容类型细分事件名**：`post_deleted` / `comment_deleted` / `album_deleted` / `anniversary_deleted` / `map_point_deleted`，另保留兼容期的 `media_deleted`）。**点赞/收藏：允许自赞/自藏；任何一方动作（含自己赞/藏自己发布的动态）都通知另一方，评论同口径**（传达「我在意这条内容」；「另一方」= 情侣对侧，admin 不在情侣里，2026-09-05 D6 服务端对齐）
- **交互**：点击通知跳转对应内容（动态时间轴并定位高亮该条 / 地图点位 / 纪念日卡片 / 相册详情）；内容删除通知无跳转（内容已不可见）；红点随已读消除；支持「全部已读」一键批量标记
- **边界**：通知中心始终收全部事件（站内 **12+1** 类：`post_created` / `post_liked` / `post_commented` / `post_favorited` / `map_point_created` / `anniversary_reminder` / `album_created` / `post_deleted` / `comment_deleted` / `album_deleted` / `anniversary_deleted` / `map_point_deleted`，其中内容删除 5 类均为后续补齐；`+1` = 兼容期保留的 `media_deleted`。内容删除仅站内，不进外部推送订阅）。**口径澄清（2026-09-03 随媒体 410 化）**：媒体不再独立删除（删除媒体=删除整条动态，走「内容删除」通知，见 §4.4 媒体来源模型），`media_deleted` 为历史独立媒体兼容期保留的事件类型，正常流程无触发源，前端渲染兼容保留；外部 Webhook 推送按渠道的事件订阅配置（渠道为空间级、admin 后台管理，见 8.3，订阅 7 类）。点赞/收藏通知仅站内+按渠道订阅同发（事件 `post_liked`/`post_favorited`）

## 5. AI 模式 — 对话界面

### 5.1 界面结构

- **顶部栏**
  - [设置]（跳转设置页，可在设置页切换回传统模式）
  - "我们的 AI 助手"
- **对话区域（主体）**
  - 消息气泡：AI 消息左对齐、浅暖灰底；用户消息右对齐、主色调底
  - 用户消息可携带媒体附件（图片/视频/音频，随消息展示 + 历史回显）：`media: [{name,type,size,data_url}]` 仅为展示引用，确认执行时才上传转正——新照片只能以「发布动态」落库，不能直接进相册（相册媒体一律从动态时间轴中选取）
  - 操作确认卡片（嵌入对话流）：预览内容（文案/照片/相册名等）→ [确认执行] [取消] → 确认后变为已执行状态；确认执行时若携带媒体附件，客户端先上传换 token 随确认提交；卡片单次有效，15 分钟未处理自动过期（显示「已过期」，不可再确认）
  - 搜索结果卡片：匹配的动态/相册/地点缩略图；卡片内联展示（点击看大图/全文，不做跨模式跳转）
  - 快捷指令 chips（进首版，静态文案，点击填入输入框）："帮我发动态" / "整理最近的照片" / "上次去海边是什么时候"
  - AI 生成进行中：输入区右侧显示「停止 ■」按钮，可中止本次输出（「结束」以确认卡片处理结果为准）
- **底部输入区**
  - [附件]（可发图片/视频/音频给 AI，均为文件附件常驻入口）
  - 文本输入框（支持多行）
  - [发送]
- **视觉风格**
  - 背景：暖灰色 #F0EDE8
  - 气泡：无尖锐棱角，padding 宽松
  - 字体：与传统模式一致，保持品牌统一
  - AI 头像：专属标识（区别于伴侣头像）
  - 整体氛围：安静、专注、可信赖

> **会话模型**：单一持续滚动会话，无会话列表/新建/切换；历史按保留时长自动清理。语音输入列入路线图，首版不提供。

### 5.2 AI 能力范围

AI 模式通过后台 MCP 工具覆盖**业务数据操作**（动态/相册/照片/地图/纪念日/互动及其查询统计，共 26 个工具）；系统配置、模型管理、账号、审计、回收站不设工具（工具定义见 DESIGN.md《MCP 工具接口清单》）：

| 能力 | 示例指令 | 对应 MCP 工具 |
|:---|:---|:---|
| 发表动态 | "帮我发一条动态，记录今天去看了电影" | create_post |
| 管理相册 | "把上个月去海边的照片整理到一个新相册" | suggest_photo_grouping + create_album |
| 查询历史 | "我们第一次一起旅行是什么时候？" | search_posts |
| 纪念日管理 | "下个月纪念日提醒我提前三天" | configure_reminder |
| 足迹记录 | "帮我把今天去的这家餐厅记到地图上" | create_map_point |
| 互动操作 | "给 TA 刚发的那条动态点个赞" | toggle_like |

### 5.3 设计原则

| 原则 | 说明 |
|:---|:---|
| 辅助而非替代 | AI 生成内容必须经用户确认/微调后才生效，不自动发布 |
| 纯对话，零配置 | 界面中不包含任何配置入口 |
| 隐私优先 | 隐私控制在设置页配置，AI 模式自动遵循 |
| 操作确认 | AI 生成预览 → 发起人确认 → 生效 |
| 操作审计 | 所有 AI 操作记录在操作日志中可追溯 |

## 6. 视觉与体验规范

### 6.1 风格定调：iOS 原生 · 伴侣协作

| 风格 | 优势 | 劣势 | 适配度 |
|:---|:---|:---|:---|
| 可爱 | 年轻用户接受度高 | 容易幼稚化，男性用户可能排斥 | ★★★ |
| 浪漫 | 情感氛围强 | 视觉疲劳快，日常使用不够耐看 | ★★★ |
| **iOS 原生风格** | **熟悉顺手、久看不腻、男女通吃；毛玻璃/系统组件最贴合情侣日常记录** | 个性表达弱 | ★★★★★ |

> **核心感受**：以 iOS 原生语言承载——系统浅灰底 + 白色卡片/列表 + 暖粉主色 + 毛玻璃导航栏与 tab bar。不做强调「设计感」的定制主题，回归「这是一个认真做记录、每件事都顺手」的情侣 app：熟悉、温馨、好用。

### 6.2 色彩体系（iOS 风格）

**设计定调**：系统浅灰底 #F2F2F7 + 白色表面 + 暖粉主色；暖粉只用于着色点/FAB/选中，强调文字与图标用深档粉保证对比度；iOS 语义蓝仅用于操作；危险红仅用于破坏与未读。

| 用途 | 浅色 | 深色 |
|:---|:---|:---|
| 背景 | #F2F2F7 | #000000 |
| 表面（卡片/列表） | #FFFFFF | #1C1C1E |
| 主色（着色点/FAB/选中） | #FF8FAB | #FF8FAB |
| 强调色（文字/图标） | #F06292 | #FFB4C2 |
| 操作色（iOS 蓝） | #007AFF | #0A84FF |
| 破坏/未读 | #FF3B30 | #FF453A |
| 正文 | #1C1C1E | #F2F2F7 |
| 次要文字 | #8E8E93 | #98989F |

> **强调色（暖色系预设，深浅各一套）**：柔雾粉 rose（浅 #FF8FAB/#F06292、深 #FF8FAB/#FFB4C2）；蜜桃橙 peach（浅 #FF9F7A/#E35F3D、深 #FF9D82/#FFC4A6）；落日金 gold（浅 #F2B441/#CF8A1C、深 #F2B441/#FFD98B）；豆沙红 dousha（浅 #E0786E/#B94D4D、深 #E0877F/#F0B0A9）。

### 6.7 多设备响应式（三档）

单代码库纯 CSS 断点适配，无独立桌面版；iPhone 形态为基准，向上增强。**断点边界 = 768px / 1280px**（桌面门槛提到 1280 是为了让 iPad Pro 11/13″ 落在平板档）。

| 档位 | 视口宽度 | 布局 |
|:---|:---|:---|
| 手机 | < 768px | 底部 tab bar + 右下角 FAB，主壳最大宽度 480px 居中（基准形态） |
| 平板 | 768–1279px | **底部 tab 拉满视口宽度**；主壳 100% 宽无居中；内容区由各视图自管左右内边距；iPad Pro 全系归此档 |
| 桌面 | ≥ 1280px | **浮动圆角面板**（Stage Manager 风格）：主壳居中、宽 832px（含 92 左导航 + 720 内容列）、高 `100% - 32px`、margin 16px、圆角 18、白底 + 大阴影；body 渐变背景透出画布感；FAB 贴面板右下角 |

实现约定：

- 主壳 `.main` 与独立整页（登录 / 通知 / AI 对话 / 设置 / 聊天）在桌面档统一走「浮动圆角面板」形态，且**尺寸完全一致**：宽 ≤832px（`width: calc(100% - 32px)`）、高 `100% - 32px`、`margin: 16px auto`、圆角 18、白底 + 同一软阴影。**登录页在登录前后必须是同一个框**（含四边外距）。
- 框架尺寸由 `--frame-max` / `--frame-inset` / `--frame-radius` / `--frame-shadow` 单点定义：手机 480px / 平板 100% / 桌面 832px；外距、圆角、阴影只在桌面档有值（16px / 18px / 大阴影），手机平板为零值（全屏、无卡片）。`--col-max` 只负责**内容列**宽度（480 / 100% / 720）。
- 底部弹层在桌面档从面板**下边缘**升起：遮罩留出与面板相同的外距、弹窗与面板等宽等圆角，内部标题 / 正文 / 按钮收在 520px 对话框宽度内；手机 / 平板仍贴屏幕底部（原生 sheet 手感）。
- 全屏层（大图查看器、相册「选择」页）在桌面档同样收进面板矩形（同外距、同圆角），不铺满整个浏览器窗口。
- 实现细节与踩过的坑见 [DESIGN.md](DESIGN.md) §15。
- 平板档各视图的左右内边距由视图自带样式承担（参考各 view 现有 16-24px），不强制统一 token。
- 照片墙、相册卡片等网格使用 `auto-fill + minmax` 随容器宽度自适应列数。
- 不做 PC 双栏仪表盘（保持 iOS 单栏心智；如未来需要另行立项）。

## 7. 数据操作规则（用户可见行为）

### 7.1 核心原则

> **只增不删（软删除），不可编辑，回收站兜底**
>
> **适用范围**：仅约束**记录内容**（动态、评论、相册、照片、纪念日条目、地图点位）。**配置信息不受此限**——用户资料（头像/昵称/生日）、空间配置（空间名/空间签名/恋爱开始日期）均可随时修改。**点赞与收藏是可撤销的关系数据**：取消即失效，不进入回收站，不属于记录内容。

| 操作 | 是否支持 | 说明 |
|:---|:---|:---|
| 添加 | 支持 | 创建动态/评论/相册/纪念日/地图点位 |
| 删除 | 支持 | 情侣双方均可软删除空间内任意记录内容（含对方发布）→ 进入回收站；删除对方发布的内容时向对方发站内通知（删除自己的内容静默） |
| 编辑/修改 | 记录内容不支持 | 动态/评论/相册/照片/纪念日/地图点位等记录内容不可二次编辑；配置信息（用户资料、空间名/签名/恋爱开始日期）可修改 |
| 恢复 | 支持 | 仅管理员可在后台管理页面从回收站恢复 |
| 永久删除 | 系统自动 | 仅由系统按配置期限自动执行，用户/AI 均不可手动清理 |

### 7.2 对各界面的影响

| 界面 | 变化 |
|:---|:---|
| 传统模式 | 所有详情页移除「编辑」按钮；记录内容的删除入口统一为**长按条目**（不设常驻删除图标），确认动作一律写「移入回收站」（见 DESIGN §13 删除交互统一规范） |
| AI 模式 | AI 回复中不再提供「修改」选项；确认卡片仅有 [确认] [取消] |
| 后台管理 | 回收站管理模块 + 保留期限配置 |

> 回收站的自动清理规则、安全约束与工具层影响见 DESIGN.md《回收站机制》。

## 8. 需求决策与页面清单

### 8.1 产品设计决策

| 决策项 | 最终方案 |
|:---|:---|
| 产品定位 | 情侣生活记录与情感管理应用 |
| 界面架构 | 双模式：传统模式 + AI 对话模式 |
| 传统模式风格 | iOS 原生风格（系统浅灰底 + 白卡 + 暖粉主色 + 毛玻璃） |
| AI 模式形态 | 独立全屏对话窗口 |
| 切换方式 | 设置页切换传统模式/AI 模式 |
| 视觉区分 | 传统=iOS 原生（浅灰底白卡暖粉）；AI=暖灰极简丰富交互 |
| AI 配置位置 | 仅在后台管理页面，客户端设置页仅体验偏好 |
| MCP 工具管理 | 后台内置预定义，客户端不可见不可改 |
| 客户端职责 | 纯展示 + 调用，零 AI 配置 |
| 数据操作 | 只增不删（软删除），记录内容（含评论）不可编辑，回收站兜底；配置信息（用户资料/空间配置）可修改；点赞/收藏为可撤销关系数据，不进回收站；删除权双方对等（含对方内容），恢复仅 admin |
| 互动功能 | 点赞 / 收藏 / 评论 全量保留；APP 可用，AI 经 MCP 工具代理（写操作需确认） |
| MCP 工具范围 | 仅业务数据操作（26 个）；系统配置/模型/账号/审计/回收站不设工具；get_memory_digest 移除；delete_photo 已移除（删除照片=删除所属动态，走 delete_post）；get_visited_cities 已移除（城市列表由地图点位统计提供） |
| 快捷仪式入口 | 无专用快捷仪式入口（纪念日经 FAB 创建）；写封信、许个愿列入路线图，首版不实现 |
| 媒体来源 | 媒体仅随动态上传（图片/视频/音频多选，可纯媒体=一条动态）；无独立上传/独立删除（删除媒体=删除整条动态）；相册=媒体池的组织视图（一文件一相册、跨相册 409）；历史独立媒体只读兼容（不可新建，独立媒体接口 410） |
| 媒体管线 | 两段式上传（临时区→发布引用）；图片上传时生成缩略图，视频用占位图（不引入 ffmpeg）；EXIF 取拍摄时间、忽略 GPS；临时区孤儿 24h 清理 |
| 媒体查看器 | 一个查看器覆盖三类：**照片**（双击/滚轮/捏合缩放）、**视频**（居中播放按钮 + 原生控制条）、**录音**（封面 + 日期/时长 + 播放按钮 + 原生控制条），顶部有类型标识；**视频/音频点了才播**——不做自动播放（浏览器会拦掉带声音的 autoplay，也避免进详情就出声）；单条切换/关闭时停掉上一条；文件损坏或格式不支持给明确提示（保存入口仍在）；时间轴 / 动态 / 相册三处共用（见 DESIGN §16） |
| 媒体另存到本机 | 支持单条「保存」（全屏查看器底栏，照片/视频/音频同一入口）：手机走系统「另存为」（Android SAF，零存储权限、用户自选去处），Web/无 Tauri 环境降级为浏览器下载；无批量、无保存通知；**不是**数据导出/备份（后者不提供，见 DESIGN §11.3、§14） |
| 底部导航 | 五个 tab：首页 / 动态 / 相册 / 纪念日 / 地图；另设右下角浮动添加按钮（FAB，四项：记动态/添加地点/纪念日/相册）；通知/设置入口收敛为一级 tab 页，AI 页仅设置（见 4.8） |
| 通知中心 | 独立通知列表页，入口=一级 tab 页右上角铃铛（AI 页仅设置、二级页无入口） |
| 通知模型 | 站内=通知中心全量收录+红点（不可关，点开即消），不设站内通知开关；外部推送按渠道事件订阅；删除对方发布的内容发站内通知（自删静默，修订 v1.2「删除无需通知」适用范围） |
| 纪念日重复 | 全部按年重复，无一次性 |
| AI 会话/输入 | 单滚动会话；首版文字+附件（图片/视频/音频，均为文件附件常驻入口）；语音输入列入路线图 |
| AI 确认卡片 | 单次有效；15 分钟未处理自动过期（过期后可见不可确认） |
| 对话保留时长 | 预设 7/30/90 天/永久，默认 30 天（按用户生效） |
| 数据导出 | 不提供——备份与迁移由部署者直接拷贝自包含数据目录完成（见 DESIGN §11.1/§11.3） |
| AI 可用性 | 不设功能开关：后台配置模型 Key 即可用；无 Key 时 APP 的 AI 模式切换项置灰提示 |
| APP 本地缓存 | 自动管理（上限 + LRU 淘汰），设置页不提供手动清理入口 |
| 帮助与反馈 | 不提供（自部署无接收方）；保留「关于」（版本号/服务端地址/项目主页） |
| 后台仪表盘 | 内容统计 + AI 调用量/Token 消耗/平均延迟 + 异常告警（全站唯一监控入口）；无成员活跃度 |
| 后台信息架构 | 扁平 6 项按管理对象分组：仪表盘 / 空间管理（信息+成员+保留策略）/ AI 配置（接入与模型/提示词与风格/MCP 工具/访问令牌）/ 外部集成（通知渠道/地图配置）/ 回收站 / 审计日志；同类内容一处一事——监控归仪表盘、两类保留策略归空间管理、PAT 归 AI 配置 |
| 心情标签 | 温馨系预设 + 自定义输入 |
| 草稿 | 不提供草稿功能 |

### 8.3 后台管理页面功能范围（admin）

登录：统一登录系统，**仅 admin 角色可登录**。后台导航为扁平 6 项：仪表盘 / 空间管理 / AI 配置 / 外部集成 / 回收站 / 审计日志（按管理对象分组，同类内容一处一事；路由与实现见 DESIGN.md 第 9 章）。admin 能力清单：

- **仪表盘**：全站唯一监控入口——内容统计（单空间口径）/ AI 调用量与 Token 消耗与平均延迟 / 最近活动 / 异常告警
- **空间管理**（管理对象 = 本空间，信息/成员/保留策略三类同页）：
  - **空间信息**：名称 / 个性签名 / 在一起日期与在一起统计（同一张卡）
  - **情侣成员**：情侣账户一次性同时创建（双方用户名/昵称/密码一次提交，任一情侣角色已存在则服务端拒绝）；建立后仅可修改昵称、重置密码；用户名/角色不可变更、不提供删除；admin 账号只读展示
  - **数据保留**：回收站保留期限（7~365 天，默认 30）/ AI 对话记录默认保留时长（空间级默认值，用户可在 APP 自行调整）——两类空间级保留策略集中于此，回收站页仅只读展示期限
- **AI 配置**（4 个 tab，嵌套路由 /ai/* 可直达）：
  - **接入与模型**：AI 供应商管理（协议类型 OpenAI Chat Completions / OpenAI Responses / Anthropic / Gemini + 地址 + API Key，Key 加密存储）、供应商排序（有序故障切换链：从第一个开始，失败依次向下）、获取模型列表并勾选默认模型（模型级参数可选，不设置即调用时不传）、语义检索嵌入模型（供应商限 OpenAI Chat 协议 + 显式模型名；可关闭，关闭或调用失败时 AI 搜索回落关键词匹配）
  - **提示词与风格**：System Prompt 模板（主干）、输出风格库（内置固化 + 后台自定义，设全局默认风格）
  - **MCP 工具**：内置工具启停
  - **访问令牌**：PAT 生成/吊销（只读/读写档位，仅绑定情侣用户；PAT 唯一用途是外部 Agent 的 MCP 通道凭证，故归 AI 域）
- **外部集成**（出站第三方依赖中除模型 API 外的两类；2 个 tab，嵌套路由 /integrations/* 可直达）：
  - **通知渠道**：空间级外部推送渠道（通用 API Webhook）——渠道配置（请求方式 GET/POST/服务地址/请求头/请求体模板占位符）、按渠道订阅事件（纪念日/新动态/评论/点赞/收藏/足迹/相册上新）、预设模板（Bark/Server酱/Qmsg/企业微信）、[发送测试]
  - **地图配置**：瓦片源多卡片管理——已保存源以等高卡片网格展示（类型限公开 XYZ 模板 / 天地图密钥认证两种，可添加多个），末尾固定「添加瓦片源」卡；卡片支持启用（全局至多一个使用中）、删除，**不提供编辑**（配置有误删除后重加）；密钥加密只存服务端
- **回收站管理**：查看已删除内容（按类型筛选、显示删除者）/ 恢复（二次确认，批量支持）/ 回收站操作日志（恢复 + 系统超期永久删除；保留期限提示只读展示，读自空间管理·数据保留）
- **审计日志**：AI 操作日志 / 外部 MCP 调用日志（PAT 来源）；模型响应延迟与用量报表归仪表盘（见上），不在本页
- **布局约定**：整页 flex 视口锁定（页面不滚动），各数据容器（表格/列表卡片）内部滚动，长列表表头固定；操作反馈统一走全局 toast，不使用原生弹窗（危险操作确认用应用内对话框）

> **明确不提供**：备份/导出/导入（部署者直接拷贝数据目录）、AI 功能开关（无模型 Key 即不可用）、成员活跃度等运营类仪表、情侣用户的密码自助找回（由 admin 重置）。
